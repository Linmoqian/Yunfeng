# 决策层

`proposal.ts` 校验模型局部提案；`engine.ts` 维护目标树、排序、预算与实测反馈；`types.ts` 定义持久化契约，`relations.ts` 校验层级调整，`store.ts` 使用内置 `node:sqlite` 保存检查点与关系（Node ≥22.13）。复用 TaskStore 和 Pi SDK，不引入工作流框架：这里只有一个串行、有界、可恢复的事件状态机，新增运行时会重复状态来源。

模型提出最多五个任务与五个分组，规则按 `收益 × 0.5 + 成功概率 × 0.3 − 成本 × 0.2` 选一个任务交给 Pi 规划。每轮重新观察、更新最多五个待选节点。估计值均在 0–1 范围；预算默认 10 个相对成本单位，不表示金额、GPU 时间或已测资源消耗。

树最多 100 个节点、四层；每个任务最多尝试两次。相同观测文件和 Git 状态下，相同计划不得重复执行。验收条件首次确定后锁定；子任务通过不代表长期目标达标。等待事件、要求人工信息、停止探索会分别进入 WAITING 或 PAUSED。模型不具备工具、扩展或持久聊天会话。

检查点采用新增可选字段，旧任务在下一轮规划时建立决策树；未知作业仍按原恢复规则暂停。补充人工目标时重建树，保留预算消耗。执行前预留成本与记录作业身份，崩溃后不自动重跑或退还估计成本。

节点关系保存在数据目录 `research.sqlite` 的 `research_node` 表，父子外键限定同一任务；节点历史、预算与 Runtime 检查点在同一事务提交。旧科研 JSON 首次加载时导入，原文件保留为备份；后续只读取数据库。普通开发任务继续使用原有 JSON。备份旧 JSON 不代表最新进度，降级前需导出数据库快照；不要用旧服务覆盖新数据目录。

决策提案的可选 `relations:[{node,parent}]` 每轮最多十条，先合并候选再整体校验关系，支持整理目标树而不重置节点身份与实测结果。程序调用现有关系图组件的 `move(node,parent,revision)`，成功通过现有 SSE 发布；不唤醒已暂停任务，也不执行实验。规划、执行、反思或待审批期间拒绝外部修改，避免覆盖当前决策。
