# 本地 Hook 层

调用链：事件 → Hook Layer → Context Builder → Decision Layer → Pi 节点规划 → execute → 作业完成事件。常驻的是 Server、任务检查点和事件监听；Pi 按阶段创建临时无工具会话，不持续聊天。

`layer.ts` 是任务的本地事件入口和有界派发器；`types.ts` 定义事件与纯筛选 Hook。复用现有 TaskEventHub 记录检查点与 SSE，使用 Node 原生文件通知和已有作业回调，不新增事件服务、线程池或工作流依赖。TaskStore 是唯一业务状态来源。

- 生命周期 Hook：启动、工程师继续、服务恢复时重新观察。
- 作业 Hook：结果先持久化，再发出完成事件；重复、过期结果不能再次唤醒。
- 审批 Hook：仅继续已确认的完整计划，不重新生成未经确认的动作。
- 文件 Hook：`files.ts` 跟踪最多八个观察文件，比较内容摘要，忽略未跟踪文件和相同内容；最多监听项目根及前三个观察路径的最近既有父目录。目录创建事件触发重绑，订阅后回读封闭观察间隙，监听不递归。

通知 ID 最近 128 条去重，事件队列最多 32 项，文件事件合并成最多八条路径。文件批处理使用一次性 50 ms 窗口，Hook 文件派发也最多等待一次 50 ms；这是事件合并，没有定时模型轮询。文件读取、目录重绑各只有一个运行单元和一份待处理变化。繁忙、作业运行或等待审批时保留事件；运行单元释放、作业完成或审批通过后重新派发。

Context Builder 重新读取项目、文件、Git 和任务事实，附上触发原因。事件排队期间内容已被观察过时跳过模型，不消耗轮次；决策模型认为无行动价值时选择 wait，Pi 规划不被调用。任务状态更新和助手消息不反向唤醒，避免自身通知循环。文件 Hook 错误会暂停并回收任务资源；暂停、完成、失败或关闭停止接收事件。

最新触发批次保存在 `autonomy.trigger`，随 TaskStore 状态与现有事件记录持久化。排队通知只存在内存；服务重启后通过恢复 Hook 重新观察真实状态，不承诺恢复离线期间的每个瞬时文件事件，也不重放未知作业。Git 在每次触发时重读，当前没有独立 Git 元数据 Hook。训练命令复用本地作业完成 Hook；机器人、传感器、远程训练平台和 Pi 扩展生命周期适配器尚未接入。

扩展时由受信任的本地适配器提供事件，并通过 `ResearchHook.accept` 筛选触发原因。Hook 仅决定是否重新观察，动作仍由 Decision Layer 与 execute 决定；不开放模型注册 Hook 或直接执行副作用的入口。
