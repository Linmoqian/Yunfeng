# yunfeng 界面精简

目标是减少常驻文字和重复层级，同时让入口可发现、动作可识别、重要状态可见。先读取项目 `AGENTS.md`，并以当前组件和运行能力为准。

普通组件或功能接入任务也使用本技能检查共享控件、样式和信息层级；按当前任务范围修正问题。明确要求精简时执行下列文案与布局减法，不将所有 UI 任务自动扩大为全页精简。

## 判断哪些内容可以精简

| 内容 | 处理方式 |
| --- | --- |
| 标题已表达的介绍、重复的副标题、卡片宣传语 | 删除渲染，避免留下空容器与间距 |
| 新建、导入、终端、设置、添加、移除等熟悉动作 | 复用现有图标按钮，保留名称提示、禁用状态和原事件 |
| 方法、输入格式、快捷键、较长操作帮助 | 使用 Ant Design `Popover` 或已有折叠详情，按需查看 |
| 项目名、文件名、单位、参数值、来源和运行状态 | 保留辨识所需的信息；较长记录可进入详情 |
| 错误、保存失败、刷新失败、执行确认、删除影响 | 保持可见，并给出真实的下一步 |
| 估计值、演示数据、未支持能力、科研解释限制 | 简短明确地展示；不能通过删文案制造已支持或已验证的印象 |
| 入门引导正文、必须填写的格式要求 | 判断其是否直接帮助完成当前操作，不因文字较长就隐藏 |

避免用 CSS 批量隐藏所有 `p`、`small` 或 hint：同一个类可能同时承载帮助、结果、状态和错误。

## Yunfeng 已有实现

- Ant Design 的 Button、Dropdown、Popover、Popconfirm、Input；通过现有 ThemeProvider 使用 Yunfeng 浅白淡紫和圆角 token，图标使用 Lucide。
- `WorkspaceShell` 与 `DockPanel`：共享三栏、调宽、折叠、互换及紧凑展开入口。工具页面通过插槽接入。
- `WorkspaceTabs`：标签菜单与键盘导航；`AppContextMenu`：编辑选区和自定义右键菜单。
- `TitleBar` 与 `useWindowControls`：原生窗口拖动及按钮；`useSharedComponent`：Rust 快照和独立组件窗口同步。
- 熟悉动作采用图标时保留 aria-label、可访问提示及原事件；桌面紧凑按钮沿用既有尺寸，触摸入口至少 44 px。

## 修改时同时压缩布局

删说明后检查卡片最小高度、两行网格、按钮最小宽度、底部摘要和弹窗固定高度。文字消失但空白仍占位，不算完成精简。

工具列表可将图标、名称、状态和动作排成一行；“已添加”可用带可访问名称的勾选图标表示，暂不可用状态仍可辨识。图标化不应把整段导航隐藏或移除入口。

在共享组件层解决重复模式，在业务 CSS Module 中处理局部布局。不要为了图标化重新实现下拉菜单、对话框、焦点管理或业务状态。

## 参考经验与 Yunfeng 核对项

- **选择器残留文字**：参考仓库曾因共享触发器样式留下可见字形。Yunfeng 使用 Ant Design，依据当前 DOM 核对业务选择器及可访问名称，不套用参考仓库的 Radix 选择器。
- **删文案留下空条件**：移除 `{condition && (<span>…</span>)}` 的子节点时，同时检查条件表达式，避免空括号导致解析失败。
- **描述与状态混用类名**：保留对话框语义；不要隐藏同样使用描述类名的“正在保存”等真实状态。
- **能力说明包含关键限制**：提取简短限制保持可见，再把解释放入详情。例如“团队仅保存在本机，跨设备同步尚未接入”。
- **界面名称变化影响验证**：同步既有测试中的可访问名称断言，例如工具中心名称改为“工具”；不新增仅匹配实现文字的测试。
- **热更新未反映最新样式**：先确认当前页面与运行服务，必要时重载后截图。重载会丢失未保存输入，先判断当前页面是否可安全重载。

## 核对与交付

先查看 Git 状态，标记工程师已有改动。修改已被工程师编辑的文件时，隔离本次差异；不要为提交本次 UI 改动而一起暂存原有重构、配置或未跟踪文件。

按当前项目规范执行静态检查：在 `app/` 执行 `pnpm exec tsc --noEmit` 和受影响的现有 Node 测试，并执行 `git diff --check`。当前没有 ESLint 脚本，不声称已执行。实现后只运行受影响的少量核心测试，不默认运行全量测试或生产构建。

界面改动需在可用运行环境截图，检查字体、间距、图标、裁切、重叠和禁用状态。按影响范围验证图标入口、菜单、说明浮层、键盘聚焦、Escape 关闭及焦点归位；涉及移动端时核对移动布局。不要把 Web 预览当作原生文件导入、计算、SSH、摄像头或真实设备验收。

只暂存核对过的本次文件或差异，检查实际提交内容，使用项目约定的中文 Conventional Commits 标题。提交后检查剩余状态，保留工程师原有工作。

交付简短说明：精简范围、静态检查结果、截图环境、未验收能力和提交。不要因请求范围很广就声称所有页面、数据状态和原生流程均已验收。
