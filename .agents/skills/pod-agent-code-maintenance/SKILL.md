# pod-agent 代码维护

将指定功能收敛为职责清楚、层级合理、接口简洁的模块，让顶层只需少量调用即可完成组装。维护范围由工程师的任务决定。

## 先确认功能边界

读取根目录 [AGENTS.md](../../../AGENTS.md) 与 [开发与代码约定](../../../docs/development.md)，检查当前工作树、暂存区、目标文件差异和调用链。区分工程师已有改动与本次改动，按可独立审查的功能单元推进。

按需读取 [项目架构](../../../docs/architecture.md)；涉及 Agent 时读取 [Agent 层](../../../agents/README.md)。以当前源码中的接口、事件和数据归属为依据，先确认哪些代码可删、哪些职责需要移动、哪些调用必须兼容。

## 优先做减法

- 优先删除已确认无调用的代码、重复计算、重复状态和多余中转，合并同责实现，复用已有模块。删除前核对静态引用、动态注册、平台入口和外部协议。
- 封装应减少调用方需要理解的细节。避免为单次调用引入通用框架、无行为的转发层、冗余接口或提前设计的扩展点。
- 按职责拆分复杂实现；不以行数、文件数或覆盖率指标机械拆分。必要的模块化可以增加文件，但应降低整体理解和维护成本。
- 清理迁移后失效的导出、导入、依赖和分支。兼容层仅在实际调用或数据迁移仍需要时保留，并说明保留原因。

## 按功能组织层级，封装超薄入口

- 沿用现有业务域与目录，将同一功能的组件、订阅 Hook、服务适配、类型和必要测试就近组织。只有确有跨功能复用的内容才上移到共享层。
- 每个模块对外提供少量明确的入口，隐藏内部计算、资源管理和实现类型。避免调用方穿透目录访问内部文件，也避免全量重导出造成循环依赖。
- 页面、路由、应用启动和命令入口只做依赖连接、必要边界校验与模块调用；复杂流程下沉到所属功能模块。入口变薄后，继续检查下层是否形成职责混杂的大控制器。
- 优先使用已有目录，如前端 `app/src/features/<功能>/`、Rust `commands/` 与 `services/<功能>/`。按实际复杂度建立子目录，不预建空层级。
- 新增或实质重构的代码文件顶部写简明注释，通常一至三行，说明职责、对外入口或关键边界。沿用语言的文件头约定，保留许可证、shebang 等必要头部；不写变更流水账，不为补注释批量修改无关文件。

## 前后端高度解耦

前端负责 UI 组织、交互状态、动作转发和服务事件订阅；后端负责业务计算、资源访问、业务状态与服务推送。通过明确的命令、DTO 和事件契约连接，避免任一端依赖另一端的内部实现。

- React 组件组合共享 UI；功能 Hook 管理订阅、展示状态和交互协调。科研计算、业务判定、持久化和长任务推进归属后端，不能在 UI 中重复维护。
- 前端经既有 `workspaceApi` 和 runtime adapter 发起动作、获取快照、订阅进度及结果。后端服务通过现有事件通道推送状态；不为解耦另建后端、数据库或通信体系，也不在本次范围外强制改写已有请求响应接口。
- Rust 命令层保持薄入口，校验输入后调用领域服务；服务拥有计算协调、资源生命周期和事件发布。后端不依赖页面组件、CSS、视图布局或前端内部状态。
- SQLite 继续作为业务数据唯一事实来源；前端订阅数据是用于展示的投影。数据库和受管文件访问沿用现有 Rust 服务及 `ManagedStorage`。
- 订阅支持准确清理，异步结果核对请求与会话归属；取消、失败和恢复通过契约表达。迁移期间保留已有并发、事务、权限与资源释放语义。
- Agent 逻辑继续位于独立 TypeScript 包 `agents/`，与运行宿主通过显式输入、回调和受控工具接口连接；底层工具按项目规范由 Rust 承担，平台依赖留在宿主适配层。

## 先完成代码，再聚焦验证

先完成实现与调用迁移，再执行静态检查并补充必要测试。不以测试驱动或全量覆盖作为默认流程。

- 按实际改动执行类型、lint、格式或编译检查；命令与范围遵循 [测试与 CI](../../../docs/testing.md)。公共配置或平台覆盖发生变化时执行 `pnpm check:platform-config`。
- 测试脚本只覆盖少量核心功能：优先验证本次受影响的核心输入输出、状态转换、失败处理或资源释放。选择真正有风险的行为，不枚举所有函数、分支、页面和排列组合，不新增覆盖率门槛。
- 优先调整既有核心用例；新增测试应验证可观察结果或关键不变量，避免仅匹配实现文本或复制实现。纯文件移动和低影响可逆修改无需专门补测试。
- 本地先完成实现，再执行静态检查和少量对应核心用例；CI 继续执行分组回归。不顺带启动全量测试或生产构建，不以精简测试为由删除无关的既有用例。
- 涉及 UI 的改动按项目要求截图核对，记录运行环境。静态检查、UI 截图、原生能力与真实设备验收分别报告。

完成后核对入口是否变薄、内部职责是否收敛、旧调用是否清理、契约及必要文档是否同步。按项目 Git 规范只提交本次差异，交付说明包含精简与封装范围、实际验证结果、未验证范围和提交记录。
