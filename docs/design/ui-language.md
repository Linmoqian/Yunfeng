# Yunfeng UI 语言设计稿

## 1. 设计定义

Yunfeng 是一个用于监视全部编码任务的个人工作台。界面首先帮助工程师发现需要介入的任务，其次才展示正在运行、等待和已完成的任务。

视觉关键词：**暖色、高雅、秋天、自由**。

设计不是聊天机器人外壳，也不是缩小版 IDE。首屏只回答三个问题：

1. 哪些任务需要工程师介入？
2. 其他任务当前处于什么状态？
3. 工程师下一步可以做什么？

## 2. 设计原则

### 2.1 注意力优先

需要批准、回答、选择或处理失败的任务始终浮到最上方。正常运行的任务保持安静，不争夺注意力。

### 2.2 空间自由

任务数量按日常不超过 5 个设计。使用宽松留白、非对称但稳定的构图，不用密集网格填满页面，也不引入自由拖拽和复杂面板系统。

### 2.3 状态必须真实

只展示后端能够证明的当前阶段和动作，不生成推测性的百分比。颜色、图标和动画都不能成为理解状态的唯一方式。

### 2.4 一处视觉记忆点

枫叶是唯一的品牌性图形。它承担状态语义，不作为背景纹样或季节装饰。界面不使用落叶动画、木纹、纸张噪点、橙红渐变和发光 AI 球体。

### 2.5 克制而非冷淡

高雅来自字体、比例、留白和色彩层次，不来自金色描边、玻璃拟态、大面积阴影或装饰性插画。

## 3. 色彩系统

所有组件只引用语义变量，不直接写十六进制颜色。

### 3.1 浅色主题：秋日晴空

| Token | 名称 | 色值 | 用途 |
| --- | --- | --- | --- |
| `--canvas` | 雾岩 | `#F2F3EF` | 页面背景，带轻微冷感以平衡暖色 |
| `--surface` | 素纸 | `#FBFAF6` | 任务表面和聚焦页 |
| `--surface-raised` | 晨白 | `#FFFDF9` | 需要介入的抬升表面 |
| `--text-primary` | 墨栗 | `#292720` | 标题与正文 |
| `--text-secondary` | 灰苔 | `#67675F` | 项目、时间与说明 |
| `--border-subtle` | 枯枝灰 | `#DAD8CF` | 普通边界和轨迹线 |
| `--border-strong` | 石褐 | `#B9B4A7` | 聚焦、选中和分隔 |
| `--accent` | 熟铜 | `#A35F3B` | 主操作、运行状态与焦点 |
| `--attention` | 枫绯 | `#8B3E35` | 需要工程师介入 |
| `--positive` | 松苔 | `#55705A` | 已验证和完成 |

### 3.2 深色主题：秋日暮色

| Token | 名称 | 色值 | 用途 |
| --- | --- | --- | --- |
| `--canvas` | 暮杉 | `#171A18` | 页面背景，不使用纯黑 |
| `--surface` | 湿岩 | `#20231F` | 任务表面和聚焦页 |
| `--surface-raised` | 深苔 | `#292C27` | 需要介入的抬升表面 |
| `--text-primary` | 月纸 | `#F2EFE7` | 标题与正文 |
| `--text-secondary` | 银苔 | `#B8B6AC` | 项目、时间与说明 |
| `--border-subtle` | 林影 | `#3A3E37` | 普通边界和轨迹线 |
| `--border-strong` | 苔石 | `#53584E` | 聚焦、选中和分隔 |
| `--accent` | 暖铜 | `#D39366` | 主操作、运行状态与焦点 |
| `--attention` | 亮枫 | `#E07A6E` | 需要工程师介入 |
| `--positive` | 晚松 | `#86AD8E` | 已验证和完成 |

浅色主题为视觉基准，深色主题保持相同的信息层级，不做简单反色。默认跟随 `prefers-color-scheme`，允许工程师手动切换，选择保存在本地。

正文、次级文字、强调色在各自基准表面上的对比度至少达到 WCAG AA。按钮使用 `accent` 背景时，浅色主题使用 `surface` 文字，深色主题使用 `canvas` 文字。

## 4. 字体系统

首版使用系统字体栈，不增加字体网络请求：

```css
:root {
  --font-display: "Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", serif;
  --font-body: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI",
    "PingFang SC", "Noto Sans CJK SC", sans-serif;
  --font-mono: "SFMono-Regular", "Cascadia Code", "JetBrains Mono", monospace;
}
```

- 人文衬线体用于页面问候、任务标题和关键结论，表达“人和思考”。
- 无衬线体用于导航、正文、按钮和说明，表达“界面与行动”。
- 等宽体用于项目名、时间、路径、Git、命令和日志，表达“机器与证据”。
- 衬线体不用于长正文，不使用 700 以上的粗重字重。

建议字号：

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 工作台标题 | `32px / 1.25` | 500 |
| 任务标题 | `20px / 1.4` | 600 |
| 正文 | `15px / 1.65` | 400 |
| 操作与标签 | `14px / 1.4` | 500 |
| 项目、时间、状态证据 | `12px / 1.5` | 500 |

## 5. 枫叶元素

### 5.1 造型

使用一枚简化、略不对称的五裂枫叶。线条保持清晰，不做写实叶脉、阴影和渐变。图形以本地 SVG 实现，使用 `currentColor` 继承语义色。

### 5.2 使用位置

1. 顶部品牌标记：`24px` 线性轮廓。
2. 需要介入的任务：`16px` 实心枫叶，颜色为 `attention`。
3. 任务聚焦页：叶柄延伸为一条细轨迹线，连接开始、执行、验证和完成等真实阶段。

正常运行的任务不显示枫叶，避免图形泛滥。错误状态必须同时出现“执行失败”等文字，不能只显示红色叶片。

## 6. 工作台布局

### 6.1 页面骨架

```text
┌──────────────────────────────────────────────────────────────┐
│ 枫叶  Yunfeng                              新建任务    设置  │
│                                                              │
│ 需要你介入                                        1 个任务   │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 枫叶  修复会话恢复问题       等待选择             查看  │ │
│ │       Yunfeng · 已完成排查，需要确定实现方案             │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ 正在进行                                          2 个任务   │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 优化上下文压缩策略          正在验证 · 2 分钟前更新      │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ 等待中                                             1 个任务  │
│                                                              │
│ 已完成                                             查看 12 个 │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 尺寸与节奏

- 桌面端基准宽度为 `1280px` 以上。
- 主内容宽度使用 `clamp(960px, 82vw, 1160px)`。
- 页面左右自动居中，但任务内容在任务带内部偏左组织。
- 顶部外边距为 `48–64px`，区段间距为 `40–48px`。
- 普通任务最小高度为 `88px`；需要介入的任务为 `104–112px`。
- 间距使用 `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px` 序列。
- 圆角仅使用 `8 / 12 / 14px`，不使用大胶囊形任务卡。

页面没有常驻侧栏、图表、统计卡、拖拽面板和底部状态栏。新建任务是唯一常驻主操作。

### 6.3 分层顺序

固定顺序为：

1. 需要介入；
2. 正在进行；
3. 等待中；
4. 已完成。

没有任务的区段完全隐藏。已完成任务默认折叠为一行入口。分层内部按最后状态变化时间排序，但任务更新时不抢夺键盘焦点。

## 7. 核心组件

### 7.1 任务带 `TaskRow`

每个任务只展示：

- 任务标题；
- 所属项目；
- 当前真实动作；
- 最后更新时间；
- 一个下一步主操作。

普通任务只使用淡边界，不使用阴影。需要介入的任务使用 `surface-raised`、实心枫叶和轻微抬升阴影。每张任务带最多出现一个主按钮；暂停、终止、归档等操作收进聚焦页。

### 7.2 任务聚焦页 `TaskFocusPanel`

点击任务后，从右侧展开聚焦页，工作台保留在背景中。内容顺序固定：

1. 任务标题和项目；
2. 当前需要工程师处理的事项；
3. Agent 当前动作；
4. 任务阶段轨迹；
5. 最近产生的改动、提交、文档或错误；
6. 回答、补充要求或调整方向的输入区；
7. 收纳完整日志的“查看过程”。

聚焦页宽度使用 `min(720px, 72vw)`。小于 `1024px` 时占满页面宽度。

### 7.3 空状态与断线状态

- 无任务：`工作台暂时安静。`，下方只显示“新建任务”。
- 无需介入：隐藏整个“需要你介入”区段。
- 后端断开：顶部显示`连接已中断，任务状态可能不是最新`，保留最后一次任务状态。
- 任务失败：说明失败位置和下一步，不使用`发生错误`等模糊文案。

## 8. 动效规则

只保留两类主要动效：

1. 任务状态改变时，任务带在区段间平稳移动，持续 `240ms`。
2. 打开任务时，聚焦页从右侧展开，持续 `220ms`。

枫叶从线性轮廓过渡为实心的时间为 `160ms`，不旋转、不飘落。缓动统一使用 `cubic-bezier(0.22, 1, 0.36, 1)`。

当系统启用 `prefers-reduced-motion: reduce` 时，取消位移和缩放，只保留不超过 `120ms` 的透明度变化。

## 9. 前端实现方式

### 9.1 技术选择

- 继续使用现有 React、TypeScript 和 Vite。
- 使用 CSS 自定义属性实现设计 token 和双主题。
- 不引入 UI 组件库、CSS 框架、动画库、图标库或状态管理库。
- 枫叶使用项目内 SVG React 组件。
- 聚焦页优先使用原生 `<dialog>`，利用浏览器的焦点约束、Escape 关闭和无障碍语义。
- 工作台实时状态使用 React `useReducer` 管理，服务端事件统一转换为任务展示模型。

### 9.2 建议目录

```text
app/src/
├── features/workbench/
│   ├── WorkbenchPage.tsx
│   ├── TaskSection.tsx
│   ├── TaskRow.tsx
│   ├── TaskFocusPanel.tsx
│   ├── MapleStatusMark.tsx
│   ├── taskPresentation.ts
│   └── workbench.css
├── services/
│   └── taskService.ts
└── styles/
    ├── tokens.css
    └── global.css
```

`taskPresentation.ts` 只负责状态分层、文案和排序等纯逻辑；组件不自行推断任务状态。

### 9.3 展示模型

```ts
type TaskSection = "attention" | "running" | "waiting" | "completed";

interface TaskSummary {
  id: string;
  title: string;
  projectName: string;
  section: TaskSection;
  statusLabel: string;
  currentAction: string;
  attentionReason?: string;
  primaryAction?: {
    label: string;
    kind: "approve" | "answer" | "choose" | "retry" | "open";
  };
  updatedAt: string;
}
```

工作台只获取 `TaskSummary`；打开聚焦页后再加载任务详情。现有 Agent、Session 和 SSE 数据通过 `taskService.ts` 适配为该模型，避免页面组件直接依赖后端原始事件格式。

批准、回答和重试等操作等待后端确认后再更新为成功。提交期间禁用当前主操作并显示明确动词，例如`正在批准`，不提前显示完成。

### 9.4 CSS 组织

- `tokens.css` 定义颜色、字体、间距、圆角、阴影和动效变量。
- `global.css` 只包含重置、页面基础样式、焦点样式和主题切换。
- `workbench.css` 只包含工作台组件布局，不写全局元素选择器。
- 组件使用低特异性单类选择器；状态通过 `data-state` 和 `data-attention` 表达。
- 所有交互元素使用统一 `:focus-visible` 焦点环。

## 10. 可访问性与适配

- 所有状态都同时提供文字，不以颜色或枫叶单独表达。
- 任务分层使用语义标题，任务集合使用列表结构。
- 聚焦页打开后焦点进入标题或首个待处理控件；关闭后返回原任务。
- 键盘能够完成浏览任务、打开详情、批准、回答和关闭详情。
- 小于 `1024px` 时保持单列，聚焦页替代当前页面；手机不是首版优化目标，但不能出现横向溢出。

## 11. 验收标准

实现完成后至少验证：

1. 浅色、深色和跟随系统主题。
2. 无任务、1 个任务和 5 个任务。
3. 无需介入、单个介入和多个介入任务。
4. 运行、等待、批准、回答、失败、完成和断线状态。
5. 工作台实时更新时不丢失焦点。
6. 键盘操作、焦点返回和 Escape 关闭聚焦页。
7. `prefers-reduced-motion` 下没有位移和缩放动画。
8. `1280px`、`1024px` 和窄屏下没有遮挡或横向溢出。
9. `npm run build` 通过，并使用 Playwright CLI 截图检查浅色、深色和注意力状态的视觉层级。

## 12. 明确排除

首版不实现：

- 可拖拽和自由排列的任务画布；
- 仪表盘统计图与百分比进度；
- 多窗口、多栏 IDE 布局；
- 背景纹理、粒子、落叶和持续环境动画；
- 大型设计系统或通用组件库；
- 为手机端重新设计独立导航。

这份 UI 语言的核心判断是：**让异常主动浮现，让正常运行保持安静；以秋日色温和空间留白建立气质，以一枚具有状态含义的枫叶建立识别度。**
