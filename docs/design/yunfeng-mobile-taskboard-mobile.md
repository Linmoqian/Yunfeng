# yunfeng-mobile 任务看板移动端适配与 UI 改造计划

## 背景与现状（已实测）

- 看板为整包移植的主应用同款 Dashi 看板（`src/features/taskboard`，92 文件），自带部分响应式断点：
  - ≤840px：app-nav 降为顶部 46px 横条（primary/project nav 隐藏），workspace 全宽
  - ≤760px：任务详情属性区堆叠到顶部
  - ≤719px：AI 聊天全屏
  - pointer:coarse / hover:none 等触屏降级
- 仍属「桌面 UI 压进窄屏」：HTML5 拖拽触屏不可用；右键菜单（TaskContextMenu）无触屏入口；任务详情为侧栏式面板；视图/项目/搜索在顶部堆叠拥挤；触控目标偏小；Dashi 米色纸张风与移动端液态玻璃浅色风格不一致。

## 设计方向（需确认）

- 方案 A（推荐）：移动优先改造 + UI 统一到 yunfeng-mobile 液态玻璃浅色体系，保留 Dashi 功能语义（列、状态、优先级、关系、工作流）。
- 方案 B：仅做移动可用性适配，保留 Dashi 米色设计 token。
- 差异影响全盘样式，计划按 A 编写，落地前确认。

## 改造范围

1. 信息架构与导航
   - 看板内二级导航移动化：顶部收敛为「返回 + 项目名 + 视图切换」
   - 视图切换（Dashboard / 看板 / 列表 / 甘特 / 工作流）改横向滚动 tab 或底部弹层
   - 项目切换改底部弹层选择器
2. 看板列与卡片
   - 列容器横向滚动 + scroll-snap 吸附，列宽约 78vw（min 280px）
   - 卡片密度适配（间距 / 字号 / 圆角）
   - 交互：点击卡片 → 底部抽屉详情；长按 → 操作单（替代右键）
3. 任务详情
   - 侧栏面板 → 移动端底部抽屉 / 全屏页（含滑动关闭）
   - 属性 / 标签 / 关系 / 负责人选择器改底部弹层
4. 菜单与操作
   - 右键菜单 → 长按 Action Sheet（含触觉反馈）
   - 可点目标 ≥44px，关键操作放大
5. 视图专项
   - Dashboard：统计卡 1-2 列自适应
   - 列表视图：行高 / 触控加大
   - 甘特图：评估 dhtmlx 触摸平移缩放（高成本，可先只读滚动）
   - Workflow：xyflow 画布触控拖拽 / 双指缩放（高成本，先评估）
   - AI 聊天：已全屏，微调安全区
6. 触控与动效
   - 拖拽改造：长按拖拽，或移动端「编辑排序」模式
   - 下拉刷新、加载骨架屏、空态
   - 动效对齐移动端（220ms 缓动、reduced-motion）
7. 视觉统一（方案 A）
   - `.taskboard-route` Dashi token 收敛到移动端液态玻璃浅色 token
   - 字体 / 圆角 / 阴影 / 边框统一；深色模式可选（后续）

## 分阶段执行

- Phase 1 骨架与看板核心：导航收敛 + 列滚动吸附 + 卡片触控 + 详情抽屉
  - 验证：390×844 视口浏览、点击 / 滑动、tsc+vite 构建
- Phase 2 操作流：长按 Action Sheet、属性 / 标签 / 关系弹层、列表 / Dashboard 适配
  - 验证：交互单测 + CDP 触摸模拟
- Phase 3 高级视图与打磨：甘特 / 工作流触控评估、动效、安全区、真机
  - 验证：真机 / Tauri mobile
- 视觉统一贯穿 Phase 1-2（先样式后交互）

## 实现策略与边界

- 以「追加样式覆盖 + 组件小改」为主，避免重写 2748 行 App.tsx；Dashi 组件尽量复用
- 不动主应用看板，保持「同款」功能语义
- 甘特 / 工作流触控为高成本项，先做能力评估再决定深度
- 每阶段保持 tsc + vite 构建与 vitest 通过

## 需确认

1. 设计方向 A（统一液态玻璃浅色）还是 B（保留 Dashi 风）
2. 甘特 / 工作流触控深度：只读滚动 vs 完整触摸交互
