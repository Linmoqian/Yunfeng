# 工具设计原则

日期：2026-10-18。适用于 Yunfeng 的 Agent 工具及科研执行操作。本文记录设计约束及当前边界。第一版已接入有界仲裁、宿主固定相对成本、资源互斥与取消；价值估计与实测成本校准仍待后续实现。Markdown 为本原则的权威源。

## 少量入口，按需提供

核心工具确定为读取、修改、终端、视界四个入口，各阶段按需提供。新增工具前先判断现有操作能否表达需求；同一能力的参数、格式和展示变体不拆成独立工具。也不把所有功能塞进接受任意命令或任意 JSON 的万能入口，每个操作仍须有明确的结构和边界。

每个阶段仅提供完成当前任务所需的能力。工具数量、描述长度、参数大小和返回内容都会占用上下文，应与执行耗时一起衡量。skill 提供方法与约束，加载 skill 不自动增加权限或注册其中的脚本。

科研的 `observe / plan / execute / reflect` 是 Runtime 的四阶段契约。当前 Pi 科研会话没有直接工具，模型提交结构化计划；具体动作由 execute 校验并执行。增加能力时沿用这条路径，避免额外产生一套模型工具循环。

## 四个核心工具

| 工具 | 执行归属 | 职责与约束 |
| --- | --- | --- |
| 读取 | Rust | 有界读取项目真实内容；按路径、范围和版本返回所需片段，保留来源与截断标记 |
| 修改 | Rust | 在 execute 内修改获准内容；精确补丁应校验原文或版本，冲突时重新读取；保留现有原子写入与部分提交边界 |
| 终端 | 应用内置 Rust 终端 | 科研使用结构化 program/args，保留计划授权、作业身份、取消、完成事件及过程可见性 |
| 视界 | TS 组织领域上下文，复用现有执行与组件适配 | 将模型训练、论文收集、论文撰写、思路整理等工作抽象为统一入口；领域副作用仍经 execute |

桌面能力3已实现有界行读取与唯一原文匹配修改，沿用文本读写及批量验收。范围读取仍要求整个文件不超过64 KiB，不提供大文件分页。这里的四个工具与 Runtime 四阶段分别描述能力入口和生命周期，不能机械地一一映射。

科研接入内置终端时，必须保持无 shell 参数调用。Rust 直接接收可执行程序及参数数组，不将其拼成 shell 字符串，不直接套用开发模式的 bash 工具。TS 继续校验具体程序、完整参数和工作目录的授权，管理执行身份与暂停恢复；Rust 负责进程执行与必要的取消回收，退出结果经现有作业完成事件交回 Runtime。终端呈现与 Agent 使用同一作业的输出，展示成功不能代替进程完成或实验验收。

桌面能力3由 TS JobExecutor 管理生命周期，Rust PTY 直接启动程序；旧宿主与独立 Server 保留原无 shell 子进程路径。随机令牌鉴权、精确计划授权、作业身份、输出上限、取消和恢复回收已接入；连接故障不重放启动、不降级执行。

## 视界：领域工作的统一抽象

视界的命名来自黑洞的事件视界，职责是把模型训练、论文收集、论文撰写、思路整理等工作组织成 Agent 可理解、可推进的领域上下文。每类工作作为一种视界提供，核心工具仍保持四个入口；新增领域不直接增加模型可见的顶层工具。

| 视界 | 组织的内容 | 可核验的进展示例 |
| --- | --- | --- |
| 模型训练 | 实验目标、配置、数据、作业和指标 | 作业状态、真实训练进度、验证指标与模型产物 |
| 论文收集 | 检索问题、来源、文献与阅读记录 | 已核验的文献条目、来源引用和阅读结论 |
| 论文撰写 | 提纲、章节、论据、引用和文稿 | 已保存的章节、待补证据与审阅状态 |
| 思路整理 | 问题、假设、证据与研究节点关系 | 已整理的关系、未解决问题和下一项可验证任务 |

各类视界共同呈现目标、当前状态、关键进展、证据与产物引用、待处理事项和当前允许的操作。只加载当前任务相关的视界及其操作说明，细节按需读取。模型估计、实测事实和工程师确认分别标注；进度或文字摘要不能自行证明任务完成。

视界引用既有任务、节点、作业、文献、文稿和组件状态，复用各自事实来源。一个研究目标可以涉及多个视界，通过已有身份与证据引用关联；不再维护与数据库冲突的状态，也不在视界内部另启自主 Agent 循环。现有目标树字段 `horizon` 表示滚动规划的候选节点，与视界工具分别命名和管理。

读取视界状态用于观察；发起训练、保存文稿、整理关系或更新组件等副作用，须形成有明确参数与验收条件的操作，经 TS 仲裁与 execute 调用已有执行能力。视界只暴露已注册、具有明确结构的领域操作，不接受任意脚本或任意 JSON 执行。运行中的作业通过事件更新状态，前端沿用关系图、轻量胶囊和默认折叠的详情；工程师正在编辑时，冲突操作让出控制。

视界调用的权重须覆盖其实际展开的文件、进程、网络、模型和组件操作，不能因顶层只调用一次而隐藏成本、权限或预算消耗。已授权动作展开后仍保持执行身份与依赖顺序；失败、暂停与恢复沿用既有作业机制。第一版 read_horizon(domain) 已复用现有科研任务、资源元数据、文稿与目标树的读取投影；缺少模块时返回 available=false。训练设备、外部文献检索和领域写入仍按需接入，没有借此自动注册新执行器。

## 每次调用有权重

区分两类权重：工具操作的基础开销，以及本次调用相对于当前目标的价值。读取十行与读取整个文件、查询已完成作业与启动训练，不应使用相同估计。工具定义提供默认成本与限制，宿主结合参数、资源状态和历史实测修正。

| 维度 | 依据 |
| --- | --- |
| 目标贡献 | 对当前节点和验收条件的推进程度；模型估计须标为估计 |
| 信息增益 | 是否补足决策所需的未知事实；相同版本重复读取的价值较低 |
| 时间要求 | 截止时间和任务紧迫性，由宿主任务状态确定 |
| 执行成本 | 预计耗时、CPU、内存、磁盘、设备占用及跨进程往返 |
| 上下文成本 | 输入、输出与后续解释所需的体积 |
| 副作用风险 | 修改范围、可撤销程度及失败后的核验成本 |

只在通过硬约束的候选之间计算优先级，可采用以下形式：

```text
调用得分 = 目标贡献 × 权重 + 信息增益 × 权重 + 紧迫性 × 权重
         − 执行成本 × 权重 − 上下文成本 × 权重 − 副作用风险 × 权重
```

各维度须使用明确且可比较的归一化尺度。系数由宿主策略管理并记录版本，后续根据基准与真实调用校准；本文不指定未经测量的系数。成本未知时使用保守估计，调用方不能自行提高权重或扩大预算。

## 执行前统一仲裁

Decision Engine 决定下一目标和候选计划；调用仲裁负责判断具体操作此刻是否允许、是否值得执行，以及何时获得资源。仲裁放在 TS 编排层，Rust 执行器继续校验参数与资源边界。仲裁自身使用确定性规则，不为每个调用额外请求一次模型。

按以下顺序处理：

1. 校验工具可用性、参数、权限、任务归属、暂停/取消状态和预算。未满足的调用拒绝或等待明确条件；高分不能越过这些约束。
2. 校验前置步骤、文件版本与组件反馈。用户正在编辑或拖动画布时，冲突的组件操作让出控制；独立且已获授权的后台作业按自身生命周期运行。
3. 识别重复请求和资源冲突。同一资源的冲突写入串行，已有作业不重复启动；相同版本的只读请求可共享在途结果，返回时保留来源和版本。
4. 在允许且依赖已满足的候选之间按得分选择；同分采用稳定的入队顺序。等待时间可有限提高优先级，避免长期饥饿，仍不能绕过硬约束。
5. 执行前绑定调用身份、资源和预算；完成后记录实测开销、验收与释放结果，再由事件触发后续决策。

仲裁结果保持精简：允许、等待、拒绝，附机器可识别的原因；等待须关联资源释放、授权、文件变化或其他明确事件，避免反复询问模型。执行失败与结果未知属于执行结果，不能当作仲裁拒绝。

已经授权的计划保持步骤顺序，仲裁不能按分数重排依赖步骤或改写计划。跨任务调度只选择各任务中已就绪的操作。工程师的暂停与取消指令及时传递到执行器；不可中断的短操作完成后核对状态，不将取消表述为回滚。

## 少调用，小结果

一次调用完成一件可验收的事。合并已知且相邻的文件操作，遵守既有批次上限；命令和组件操作保持各自边界，不为凑批延迟执行或提前验收。长作业返回作业标识，由完成事件唤醒；读取进度只取新增片段。

默认返回状态、短摘要、真实指标和产物引用。文件读取限定行范围与大小，搜索限定匹配数量；截断必须明确说明。完整日志、图片、大文件和详细过程按引用取用，前端复用现有组件与轻量胶囊展示。

断线、超时或恢复后，副作用可能已经发生。先核对作业身份与真实产物，再决定后续操作；不能仅凭请求相同就重试，也不能把未收到响应视为未执行。共享只读结果须受版本或新鲜度约束，禁止用过期事实替代观察。

## 边界与验收

保持 TS 编排、Rust 执行、Pi SDK 接入模型的分层，复用现有任务、权限、数据库、终端和组件契约。科研实验副作用继续通过 execute，记忆保留来源并区分模型推断与实测事实。

当前已具备计划授权、有界批次、作业身份、取消与组件让出控制。tool-arbiter.ts 在现有入口加入宿主固定相对成本、有界等待和资源互斥；同一计划步骤不重排，完整价值评分、设备预算和实测校准仍待后续实现。

核心验证包括：高分越权仍被拒绝；冲突写入不会同时执行；依赖步骤不被重排；重复事件不重复启动副作用；暂停和人工操作时正确等待；恢复后核对未知结果；无新事实不产生无效调用。性能同时记录模型可见工具数、调用次数、输出体积、仲裁/等待耗时、执行耗时和跨进程往返，使用同一固定工作流对照。

## 已落地的第一版仲裁

策略版本1：read=1、modify=3、terminal=8、horizon=2，为宿主固定相对成本，不是实测延迟；再按输入估计体积扣分、按等待时间补分。最多8个活跃调用、32个等待调用，超限拒绝；最多保留64条不含参数或路径的计时回执。模型不能提交权重。权限在入队和实际提交时核验；取消等待不产生副作用。

同项目修改与实验命令互斥，文件读取可共享资源锁，冲突修改等待；不合并独立请求的结果，不重排计划依赖。读取可以发生在命令运行期间，因此不承诺整个项目的事务快照。组件发布和聚焦沿用当前可见性、用户操作反馈及只读报告规则。接口与限制见 [科研核心工具](../api/2026-10-18-research-tools.md)。
