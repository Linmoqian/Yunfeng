# 科研执行边界与 release 三轮对照

日期：2026-10-18。保持 TS 编排与 Rust 执行的架构。TS 管理 Hook、Pi SDK、授权、状态和作业，Rust 完成有界文件操作与验收；节点持久化、模型调用和命令运行方式沿用已有实现。

## 修改与边界

- 同次观察以及同次 Hook 的文件回读合并，最多八项，按原顺序返回内容或单项不可用结果，不缓存跨轮事实。
- execute 合并相邻 write_file，最多八项；最后一步为写入时，将真实验收带入同一次 Rust 请求。命令与组件步骤截断批次，不提前验收。
- Rust 用固定8 KiB缓冲序列化响应，减少向 TCP 的细碎写入，不另复制整帧。仍使用既有单请求连接，不引入共享内存、额外线程或执行进程。
- 桌面能力标识2启用批量，旧标识1仍用单项操作；无原生标识的独立 Server 使用 Node。通道失败不回退、不重放副作用。写入前校验整批结构与路径，I/O 失败可能部分提交；不是跨文件事务，取消只在批次提交前后检查。

接口与限制见 [科研执行契约](../api/2026-10-18-research-execution.md)，复现命令见 [脚本说明](../../server/scripts/research-live/README.md)。

## 测量方式

先对提交 `7d3a2a4` 的 release 私有通道宿主跑原四组基线，再用优化后的同一套固定36环节工作流执行五组、每组完整三轮。新增 hybridSingle 与 hybridPipe 共用同一个 release 宿主、响应缓冲、TS 代码和夹具，分别使用单项/批量接口。Node 进程内、Node 管道、Rust release 管道保留。三轮轮换先后次序，不预热、不丢弃慢轮。

UTC 系统时间记录起止点，系统单调时钟记录每环节原始纳秒与耗时。Rust 宿主和独立 worker 均为 release，Apple M4 / macOS arm64、Node v26.7.0、Rust 1.95.0；报告保存源码、宿主与 worker 指纹。固定规则替代决策和反思模型，不调用真实 LLM，不包含真实训练或桌面 UI 验收。

新报告保留540条计时及每环节原生请求提交计数。原优化前后的共同四组中，每轮36环节的结果指纹均一致；暂停状态、事件顺序、两阶段真实样本统计与 SQLite 交叉回读均通过。每轮单项请求28次，批量18次，减少约35.7%。
