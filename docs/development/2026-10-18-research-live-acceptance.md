## 选择性加载与执行边界

- 显式选择 `gzip-study` 与项目已有的 `experimental-design`，另放未选中的 `hidden-study` 和一个抛错扩展作为隔离哨兵。
- 通过 SDK `before_provider_request` 只记录脱敏标记：10 次请求均包含选中标记和科研 skill 名称，不包含未选中标记，工具数量均为 0。磁盘哨兵扩展没有执行。
- skill 的 `allowed-tools` 元信息没有扩大权限。模型仅提交结构化计划，实际配置写入、命令和组件更新都由 execute 执行。
- 只授权配置子目录及一个带完整参数的 Node 命令。指标、报告、压缩产物和运行日志由该实验程序生成；Agent 不能通过文件写权限直接改指标。程序拒绝重复阶段或覆盖报告。
- 两次执行均从真实报告更新科研组件；最终胶囊数据快照为 2,796 B、减小 7.1713%、验收通过，结论引用报告原文。

## 唤醒与恢复

1. 首轮根据未知门控事实选择等待并扩展观察路径，第二轮读取 ready=false 后继续等待。这两轮有新增事实，不属于同事实重复唤醒。
2. 对已观察的 control.json 连发 32 次 Pi 事实通知，3 秒内调用数、轮次和运行日志均不增加；越界 `.env` 通知被拒绝。
3. ready 改为 true 后通过共享事件桥通知，真实任务事件中出现 `pi_extension / facts_changed`，并包含文件 Hook 通知。Decision Layer 选择基线，execute 完成后反思并等待复核。
4. SDK 实际触发 10 对 `agent_start / agent_settled`；这些生命周期事件没有进入唤醒批次。基线完成后无额外执行。
5. 暂停后，通知返回 false；工程师侧把 reviewApproved 改为 true，任务仍无调用或执行。第一个 OS 进程退出。
6. 第二个 OS 进程从相同 SQLite 重建 TaskContext，保留 PAUSED、skill 选择、成功节点和已有基线。调用 recover 不擅自继续；显式 resume 后以 lifecycle/resumed 唤醒，模型选择优化，execute 后反思，真实总体验收通过后再沉淀验收经验。
7. 完成后通知返回 false，无追加执行。审计核对 6 个各 3 秒的静默窗口：初始等待、32 次同事实通知、基线后等待、暂停变更、重建未恢复、任务完成。
