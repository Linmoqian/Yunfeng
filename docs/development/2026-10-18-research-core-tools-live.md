# 科研四工具真实模型闭环验收

2026-10-18 在 macOS arm64 使用项目现有配置的 `glm-5.3-flash`、Pi SDK 1.2.0、实际 ResearchService 与 Rust 私有通道完成验收。TS 管理 Hook、目标树、权限、作业身份和反思，Rust 执行范围读取、精确修改及 PTY；模型没有直接工具。宿主是 debug 测试程序，不启动桌面窗口。

## 实验结果

隔离项目使用当前 `server/src/research/runtime.ts` 的7,192字节作为真实压缩语料，SHA-256 为 `964dad852f676b46568c7911972fa02d15c47a28b9c2fa6bee35ede007b6ba7a`。验收器提供操作约束，模型自行提交原始决策及计划，并选择 gzip level=9；程序实际压缩、解压和对比字节，模型不能写报告。

| 决策 / 计划 / 反思 | 4 / 2 / 3 次 |

6次失败读取出现在文件监听初始化和重绑时：夹具没有 package.json，实验报告在执行成功前也不存在；FileHooks 将不可读保留为未知状态，未触发额外模型循环。它们没有计为读取成功。终端的1次失败是工程师主动暂停后核实进程退出的预期取消；恢复后的第二次执行成功。两次计划中的按行读取与精确补丁都成功，视界包括两次 ideas 目标树读取与一次 research 报告发布。

计时使用 `performance.now()` 系统单调时钟，包含权限核验、仲裁等待、Rust 通道往返、操作及少量观测开销。终端包含程序运行、输出读取及取消回收。工具累计约489.901 ms；模型阶段另计约301.371秒，包含 SDK 准备、远程请求、生成及解析。各调用存在重叠，不把累计值当作完整流程墙钟时间。这是单次受控闭环，不能据此校准固定权重或推断稳定尾延迟。

## 验证路径

1. 模型先发现门控事实未知，补充观察；确认 enabled=false 后等待。两次有不同事实的决策有效。随后32次相同 control.json 通知，3秒静默窗口内模型请求、轮次及运行日志不增加，敏感路径通知拒绝。
2. enabled=true 经 Pi 事实桥和文件 Hook 唤醒。模型提交五步计划：按行读 README、读 ideas、唯一原文补丁、参数数组启动程序、从真实报告发布组件。仲裁使用宿主固定权重，模型不能指定权重。
3. 验收器逐项检查原始计划，再批准。批准前静置3秒，配置及运行日志不变；批准后 Rust 执行补丁并启动 PTY。参数 `$(touch injected); 空 格` 完整保留为字面值，没有生成 injected 文件。
4. 在真实 PID 存活时 pause，确认 result=cancelled、PID 已退出、旧审批无法再次批准。外部更改 finish 后，暂停状态下3秒内没有调用模型或执行。
5. 第一个 Node 进程退出，第二个从 SQLite 读回 PAUSED/cancelled、skill 和作业身份。recover 后3秒不自动执行。显式 resume 先由真实模型反思取消结果，随后沿用原节点生成新计划，补丁从 attempt=1 改为2，重新授权。
6. 成功命令退出及输出结束后提交完成事件，发布真实报告指标与结论、反思实验、实测整体验收，再反思验收结果，最终 COMPLETED。实际程序用独占锁拒绝同一 attempt 重启，日志只有1、2各一条；节点 attempts=2、status=succeeded。完成后通知拒绝，3秒内无追加执行。
7. 独立审计核对9对真实 SDK 生命周期、两个进程、三个作业引用、按行读回的文本、实际 ideas 投影、终端输出及科研组件数据。生命周期没有进入新的唤醒批次。共7个各3秒静默窗口。

仲裁的冲突排队、轻调用优先、等待取消、提交前权限重检、有界背压由核心回归覆盖；本次模型计划按依赖顺序执行，未模拟高并发压力。视界使用现有 TaskStore 的真实目标树和科研报告，没有配置独立文献、文稿或训练服务。

## 实测发现与修复

前两次验收分别发出3次、2次真实请求，均在执行前被结构校验阻断，未启动实验。诊断捕获模型把 `mission_presentation` 对象写成字符串，而原错误只说“需要结构化对象”，一次纠正仍无法定位。已明确决策提示中的 `{title,summary}` 结构，并让摘要校验错误带 `mission_presentation` 或 `candidates[index].presentation` 字段名；保留严格校验，没有把错误输出转换成计划。

修复后的成功目录为 `yunfeng-real-core-tools-3`，前两次失败目录分别为 `yunfeng-real-core-tools` 和 `yunfeng-real-core-tools-2`，均保留在本机验收产物目录。全部尝试合计14次真实请求；本表只统计修复后的完整闭环，前两次 `*-metrics.json` 单独保留，不合并成成功运行。
